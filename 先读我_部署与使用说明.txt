Oneasy 邮件助手 v1.6.6 — Windows / Mac 统一部署包

v1.6.6：修正推广邮件因退订链接token参数被误判为访问凭证的问题。仅移除明确退订链接，再进行敏感检查及AI分类；登录、改密、真实凭证和设备信息仍保守转人工。AI区分第三方销售推广与客户服务请求，非业务判断保留高置信度及可核对原文依据。对已核实的阿里邮箱完整定期改密模板，在无额外风险或凭证时本地归入每日复核，提供明确摘要；不因发件人含no-reply就统一忽略。

v1.6.5：每日群汇总和邮件汇总仅展示本期邮件，不再附带系统操作摘要或操作日志。没有业务来信和待人工复核邮件时，只展示日期、统计时段和0封数量，不显示末尾业务处理／人工复核提示。有邮件时仍保留完整清单和处理提示。后台操作台账及汇总详情中的操作记录继续保留，定时时间、负责人和@规则沿用原有配置。已经开始分条发送的旧日报按原进度发完，之后的新日报使用精简格式。

v1.6.4：运行异常只发送合并说明，不再 @ 负责人；业务来信及其复核提醒继续 @，日报只有包含业务邮件时才 @。扫描失败自动进行本地诊断：连接异常重建连接，临时访问凭据失效重新获取，限流或服务暂时异常等待重试。按连续失败次数至少等待60秒、120秒、300秒；服务指定更长等待时间时按要求等待（最长24小时）。短暂故障先静默处理，连续3次失败或需人工处理时才产生运行提醒，沿用每天去重和合并规则。权限、密钥配置和证书错误不自动改动，记录后等待管理员处理并每5分钟重新检查。只有完整扫描成功才记录恢复并取消旧的待发扫描告警。暂停停止修复，恢复或重启后接续，原邮件不重复提醒。所有诊断及恢复过程保留在操作记录，无需新增配置。

v1.6.2 群消息采用中文标题、北京时间和逐条处理建议；隐藏内部编号、原始JSON和冗长分类依据。日报保留全部业务及待人工复核邮件，系统操作按中文摘要列出，详细依据和完整操作记录仍可在助手中查看。长日报优先按段落、行和句子分条，标题显示日期及第几条／共几条。只调整群消息展示，原邮箱汇总和审计记录继续保留。

完整解压后返回上一级，双击“部署邮件助手.html”，按系统指引运行安装资源中的原生安装程序。浏览器指引页不会自动执行安装。

Oneasy 邮件助手 v1.6.1 — Windows 与 Mac 部署说明

一、版本与功能
Windows 10/11 64 位：使用 Windows 部署包。
macOS 12 或更新系统：使用 macOS 部署包，包含 Intel 和 Apple 芯片两套依赖，安装时自动选择。
界面、六个邮箱监管、AI分类摘要、敏感信息转人工、18:00复核及每日汇总、负责人维护、操作记录和配置自动保存沿用原有方案。v1.6 新增企业微信内部群机器人 Webhook，业务来信、首次处理复核、截止前复核及运行提示优先发群，群接口／网络失败或负责人未填成员账号时用 SMTP 邮件兜底。
同一即时或复核提醒只发一条群消息并 @ 已配置成员账号的当前负责人，缺失成员账号的人收邮件。v1.6.1 每天北京时间18:00按负责人归集每日完整汇总，包含未即时提醒邮件的人工复核内容；启用群提醒且负责人已填成员账号时，同步发企业微信群和原提醒邮箱，日报包含业务邮件时才 @ 该报告负责人；否则只发邮件。长内容编号分条，不截断。群与SMTP分别记录进度，群失败重试当前未成功分片，重启后继续；群分片间隔4秒，即时提醒优先。沿用现有群开关，无新增开关或按钮。
助手不自动回复客户邮件，原邮箱仍可以正常人工登录和操作。
这是本机运行的软件。管理页面只允许在运行助手的这台电脑打开，负责人收取提醒可使用其他电脑或手机。

二、先决定由哪台电脑负责监控
同一组邮箱只在一台电脑启用监控。
同时在 Windows 和 Mac 启用同一组邮箱会分别处理来信、分别发送提醒，可能造成重复。
安装另一台电脑不表示两台电脑自动同步配置和记录。
本次交付包没有嵌入公司密钥、邮箱授权码或历史记录。

三、Windows 安装
1. 完整解压 Windows 部署包，不要直接从压缩包里运行文件。
2. 双击「部署邮件助手.cmd」，允许管理员授权，等待部署成功。
3. 从桌面「Oneasy 邮件助手」打开窗口。后台随 Windows 启动；关闭窗口仍继续监控。
4. 默认安装位置：C:\ProgramData\Oneasy\MailAssistant。
5. 同机已有正式版时，部署脚本备份并短暂停止本助手服务，升级后恢复；保留连接设置、负责人、启用时间和业务记录。
6. 如果提示端口被其他程序占用，先确认旧程序身份，再由管理员处理；脚本不会强制结束其他程序。
7. 现有 Windows 部署包附带运行环境，无需另外安装 Python。

四、Mac 安装
1. 将 Mac 部署包完整解压到本地文件夹。
2. 双击「部署邮件助手.command」。若提示没有权限，在终端输入 /bin/bash 和一个空格，把该文件拖入终端，然后按回车。
3. 终端提示时输入这台 Mac 的管理员密码；输入密码时屏幕不显示字符，这是正常现象。
4. 脚本检查官方 Python 安装包、安装专用运行环境和离线依赖，创建后台服务及应用入口。首装可能需要几分钟。
5. 部署成功后从「应用程序」打开「Oneasy 邮件助手」，也可以保留到 Dock。
6. 监控后台随系统启动，独立于界面窗口。关掉窗口不停止监控；关机、休眠或断网期间无法及时收取新邮件。
7. Mac 安装位置：/Library/Application Support/Oneasy/MailAssistant。
8. 后台登记：/Library/LaunchDaemons/com.oneasy.mailassistant.plist。
9. 界面优先用 Edge 或 Chrome 的独立窗口打开；未安装时用默认浏览器打开同一管理页面。
10. Mac 首次部署不需要手工安装 Python 或开发工具；交付包包含官方 Python 安装包和两种芯片所需的依赖。运行时收信、AI和发提醒仍需要联网。
11. 同一台 Mac 再次运行部署，保留配置与记录，并建立升级备份。先保持原安装用户和路径；不要把安装目录中的 data 当成通用配置模板。

五、新电脑第一次接入
1. 打开助手，进入「邮箱与负责人」，从设置入口进入系统连接更改页。
2. 配置阿里邮箱 Client ID / Client Secret，以及 AI API 地址、模型和 API Key。
3. 在提醒发件箱设置页配置发件邮箱、SMTP服务器、端口、加密方式和客户端授权码。
4. 按需进入右上角「设置 → 企业微信群提醒 → 更改企业微信群提醒」，填写获授权内部群的「群机器人 Webhook」并勾选「启用企业微信群提醒」。群内全体成员可见内容，只用于获授权公司内部群。
5. 变更会自动保存，等待页面显示保存成功；不需要管理访问码。Webhook 为密码框，已有值留空保留，取消启用只切回邮件，不清除已存 Webhook。
6. 添加或调整负责人，填写必需的提醒接收邮箱、可选的「企业微信成员账号（用于群内@）」，再将负责人分配到需要监管的邮箱；允许多个负责人共同负责。成员账号由管理员核对，留空的人接收邮件。
   新增群内@人员时，先将新人员加入已配置的提醒群，再在「设置 → 管理负责人 → 添加负责人」填写姓名、提醒邮箱和成员账号，等自动保存；已有负责人则点其「更改」。成员账号不是群昵称，例如李涵配置的是LiHan。随后在「邮箱与负责人 → 目标邮箱的更改」保留原负责人并勾选新人员，等自动保存；需要共同负责多个邮箱时逐个设置。无需更换群Webhook；仅加入群不会自动被助手@。详细步骤见「docs/详细使用说明.html」的「场景 C：添加共同负责人／新增群内 @ 人员」。
7. 使用负责人页「发送测试邮件」验证 SMTP 投递，再启用邮箱监控。这个按钮只发邮件，保存配置不会发测试群消息。启用后只处理新收到的邮件。
8. 核对六个监控邮箱、负责人、群及发件设置；观察运行概览中的扫描状态，并用已授权的启用后新测试来信核对产品完整群提醒链路及手机、电脑 @ 通知。
仅安装和自动保存不会替你发送测试提醒。SMTP 仍发送完整日报，并承担即时和复核提醒兜底，不应因启用群提醒而省略配置；日报群发送失败不重复补发已成功的邮件。
群机器人方式不需要 CorpID、AgentID、自建应用 Secret、客户端可信 IP、可信域名或入站消息回调；无群内交互，个人微信未接入。原敏感信息不送 AI、通知遮蔽及人工处理规则继续适用。

六、原 Windows 主机迁移到 Mac
Windows 配置使用原电脑的加密保护，不能直接复制给 Mac 解密。
在 Mac 上按首次接入步骤配置一次；以后在同一台 Mac 更换负责人或升级无需重新填写密钥。
正式切换前先检查 Mac 配置及提醒投递，再停止 Windows 旧监控，最后启用 Mac 监控。
首次接入以启用时刻为边界；切换前已经存在的待处理邮件和切换间隙请人工核对。
旧 Windows 历史记录、备份仍保留在原机。本版本没有增加跨电脑历史迁移或同步功能。

七、常见问题
打开的是文本预览：在系统文件管理器中执行部署入口，不要在编辑器或压缩包预览中打开。
页面打不开：先等部署完成，检查 http://127.0.0.1:8765/，再查看安装目录 logs 中的日志。
端口已被占用：同机避免同时运行开发后台和正式服务。
收不到提醒：核对群提醒是否启用、Webhook、当前负责人分配及成员账号；查看操作记录中的群失败／缺少成员账号邮件兜底情况，并核对负责人邮箱、发件授权码、SMTP权限和网络。负责人页测试只验证邮件；群已接收但无弹出时检查群通知、@ 账号及手机／电脑通知设置。
每日汇总和时间安排：每天北京时间18:00按负责人归集并按上述渠道规则发送，不随电脑时区改变。群内所有成员均可见汇总，敏感信息仍按原规则遮蔽。
关闭桌面窗口：不影响后台；电脑须保持运行且联网，避免休眠。

八、代码位置
app/static：前端 HTML、CSS、JavaScript，共用同一界面。
app/alimail.py：阿里邮箱 API 接入。
app/core.py、ai.py、worker.py：规则、AI判断和后台扫描。
app/recovery.py：扫描故障的本地诊断及恢复策略；实际重连和重试由后台执行。
app/store.py：SQLite记录、负责人、提醒及汇总安排。
app/smtp.py：向负责人发送提醒邮件。
app/wecom.py：内部企业微信群机器人 Webhook 发送与成员 @。
app/config.py：本机加密配置。
app/windows_service.py、scripts/deploy.ps1：Windows后台与部署。
app/service_runner.py、app/macos_deploy.py、scripts/macos-install.sh：Mac后台与部署。
scripts/launch.ps1、scripts/macos-launch.sh：桌面入口。
tests：业务回归和部署辅助检查；测试不会使用交付包之外的真实邮箱密钥。

Oneasy 邮件助手 v1.6.1 — 客户端运行控制

右上角三个图标：
■ 暂停监控：暂停检测、AI分析、自动移动、提醒发送和汇总调度；管理页面保留。
○ 恢复监控：暂停后显示，恢复处理并补查仍在监控范围内的新邮件；不改变原启用时间。
↓ 隐藏到后台：只关专用客户端窗口，后台保持原运行/暂停状态。
× 完全退出：二次确认后正规停止后台并关专用窗口，配置和历史保留。
窗口自带的×仍只关界面，后台继续。

暂停状态持久保存，重启后仍需主动恢复。已经开始的读取/发送可能完成，已发送邮件不能撤回。
控制操作先尝试保存当前表单；保存失败不执行。
隐藏/退出通过本机原生助手执行，浏览器首次可能询问是否打开Oneasy邮件助手；请允许。
Windows及Mac正规停止/重新启动后台可能需要管理员授权，取消则保持未完成状态。
默认浏览器回退不能保证自动关窗口，按提示手动关闭即可；不影响正规停止后台的结果。
Mac控制仍需真实Mac验收；Windows实际验证范围见验证记录。

升级：在原监控电脑重新运行交付包对应部署脚本，保留现有配置、负责人、启用时间及记录。
新电脑仍需首次配置一次，包内不包含公司密钥或历史数据。同一组邮箱只启用一台电脑。
