Oneasy 邮件助手 v1.6.3：功能与使用说明（保留原有设置与多人规则）

v1.6.3 合并同类运行异常：一轮邮箱扫描结束后，将到期的同类故障合并为一条群消息，列出受影响邮箱并统一 @ 当前负责人；邮件兜底按负责人合并。同一邮箱同一类异常仍保留原来的每日去重规则，发送失败会重试，后台保留逐邮箱记录。普通业务来信仍即时提醒，不等待扫描汇总。

v1.6.2 群消息采用中文标题、北京时间和逐条处理建议；隐藏内部编号、原始JSON和冗长分类依据。日报保留全部业务及待人工复核邮件，系统操作按中文摘要列出，详细依据和完整操作记录仍可在助手中查看。长日报优先按段落、行和句子分条，标题显示日期及第几条／共几条。只调整群消息展示，原邮箱汇总和审计记录继续保留。

日常使用
打开 http://127.0.0.1:8765/。运行概览、业务来信、人工复核、每日汇总和操作记录保持原有用途。
“邮箱与负责人”只展示六个邮箱、用途和负责人姓名，不展开系统参数或个人资料表单。
系统仍仅辅助检测和提醒；客户回复、业务发信由人工在原邮箱操作。

更改系统配置
点击页面右上角“设置”。
“更改系统连接”：维护阿里 Client ID / Secret、AI 地址、模型与 API Key。
“更改提醒发件箱”：维护发件地址、SMTP 服务器、端口、加密方式和授权码。
“企业微信群提醒 → 更改企业微信群提醒”：维护“启用企业微信群提醒”复选框和“群机器人 Webhook”密码框。已有 Webhook 留空保留，关闭开关不清除已存 Webhook。
现有配置由后端加密保存在 data/config.json，启动时自动读取，换负责人无需重填。
仅进入更改页面才显示表单；已有密钥不回显，留空保留。
输入停止约一秒后自动保存，离开编辑页前也会尝试保存，无需点击保存按钮。
请以“已自动保存”为准。填写不完整、无效或接口失败时显示“未保存”，继续使用最后一次成功保存的配置。
更换阿里应用 ID、AI 服务地址、发件账号或 SMTP 服务器时，需要填写对应新密钥或授权码。
失败的修改可修正，也可点击“放弃未保存修改”恢复最后保存的配置。
保存配置仅代表持久保存，不等于外部连接测试成功。

企业微信群与邮件提醒
启用后，业务来信、首次处理复核、截止前复核和运行提示优先发到同一个已获授权的公司内部企业微信群。群内全体成员都能看见内容，@ 只指定提醒对象，不限制内容可见范围。
同一提醒合并为一条群消息，@ 已配置企业微信成员账号的当前负责人；成员账号为空的负责人直接收邮件。群接口报错或网络失败时改用原 SMTP 邮件提醒；未启用群提醒时继续使用邮件。
每天北京时间18:00按负责人归集每日完整汇总，包含未即时提醒邮件的人工复核内容。启用群提醒且负责人已填成员账号时，同步发企业微信群和原提醒邮箱，群内 @ 该报告负责人；否则只发邮件。长内容编号分条，不截断。群与SMTP分别记录进度，群失败重试当前未成功分片，重启后继续，不重复补发已成功的邮件；群分片间隔4秒，即时提醒优先。沿用现有群开关，无新增开关或按钮。提醒邮箱和 SMTP 配置仍需保留。
群机器人 Webhook 方式不需要 CorpID、AgentID、自建应用 Secret、客户端可信 IP、可信域名或消息回调；没有入站回调、群内领取或完成交互，个人微信未接入。
既有敏感信息不送 AI、通知遮蔽及保守转人工规则继续适用；助手不自动回复或删除客户邮件。Webhook 仅在本机设置页输入，不写入聊天、台账或交接文档。

负责人管理
进入“设置 → 管理负责人”，也可从“邮箱与负责人 → 管理负责人”进入。
“添加负责人”：填写姓名和提醒邮箱，完整且有效后自动保存；内部标识自动生成，无需填写。
“企业微信成员账号（用于群内@）”：可选，填写管理员核对的成员 userid；它不是姓名、手机号或助手内部标识。留空时使用邮件提醒。
新增群内@人员：先把人加入已配置的企业微信内部提醒群；在“设置 → 管理负责人 → 添加负责人”填写姓名、提醒邮箱和企业微信成员账号（不是群昵称，例如李涵是LiHan），等“已自动保存”；若已有负责人，点其“更改”补充账号。再到“邮箱与负责人 → 目标邮箱的更改”，保留原负责人并勾选新人员，等自动保存；多个邮箱逐个设置。无需更换群Webhook。仅加入群不会自动被助手@，还须配置成员账号和邮箱分配。即时及复核提醒合并@相关负责人，日报按负责人分别发群和原邮箱。“发送测试邮件”仅验证邮件，群@效果用经授权的新来信核对。
“更改”：进入独立页面修改姓名、提醒地址和可选成员账号，自动保存。
“移除负责人”：从当前名单和邮箱分配中移除，取消此人待发送的通知；历史邮件、日报和操作记录保留。
如果此人是某个邮箱唯一负责人，系统会拒绝移除；先为这些邮箱增加另一位负责人。
同一提醒地址不能重复添加为多个有效负责人，避免重复投递。
“发送测试邮件”是可选的独立 SMTP 测试操作，不会发送群测试消息；保存、新增和编辑本身不会发送测试提醒。

分配邮箱
进入“邮箱与负责人”，点击某个邮箱对应的“更改”。
勾选一位或多位负责人后自动保存；同一个人可以在多个邮箱被勾选。
每个监控邮箱至少保留一位负责人。监控文件夹和可选的广告邮件移动开关也在这里维护并自动保存。
选中人员接收该邮箱的即时和固定复核提醒：启用群提醒时合并 @ 已配置成员账号的人，其他人收邮件。每日完整汇总按负责人分别发群和原提醒邮箱，群内 @ 该报告负责人；未启用群提醒或未填成员账号时只发邮件。各负责人、各渠道分别记录发送进度，失败后按各自进度续发。
移除人员不再接收该邮箱待发和后续通知；已发出的邮件不能撤回。
新增或替换人员会接手尚未发出的提醒和未汇总内容，不因换人批量重发全部已发送历史提醒。
不设置任务领取、完成状态或人工确认回调。

首次接手与部署
普通负责人无需安装本助手，在企业微信内部群及提醒邮箱收取通知；邮件若要触发企业微信新邮件提示，仍需接入对应邮箱并开启通知。
维护人员在全天联网、不休眠的 Windows 或 Mac 主机按统一交付包部署指引安装；真实 Mac 安装、后台控制和开机恢复仍待验收。
后台启动后，首次从“设置”填写连接和提醒发件箱，按需配置企业微信群提醒，再维护负责人、可选成员账号并分配六个邮箱。
可手动发送测试邮件检查 SMTP 收件；群 Webhook 保存不会发测试消息。在“邮箱与负责人”完成接入检查并启用后，安排已授权的新测试来信核对产品完整群提醒链路及手机、电脑 @ 通知。
以后启动自动读取原配置。仅处理启用之后的新邮件，升级保留原启用时间。
本机管理页免访问码，仅允许本机访问；不要将此入口公开到网络。

升级与恢复
同一运行电脑：先备份 data/main.db 和 data/config.json，停止旧后台，替换 app 与 scripts，保留整个 data，再启动。
v1.2 首次启动自动把原单负责人转换为一位负责人组成的列表；原邮件、通知记录和启用时间保留，不重发已发送通知。
升级前备份与旧代码应一起保留。需要回退时，停止后台，在新目录中同时恢复匹配的旧代码、数据库备份和配置，核对待发通知后再运行；不要同时开启两套扫描。
配置使用机器加密，迁移运行电脑时在新电脑重新配置。公开源码包不含真实密钥、数据库或 Python 环境。

前后端代码
app/static/index.html：页面结构、导航与设置入口。
app/static/style.css：样式及窄屏适配。
app/static/admin.js：日常页面、数据展示、路由和通用控件。
app/static/settings.js：独立设置页面、自动保存、负责人维护与邮箱多选。
app/web.py：本机接口、连接配置、负责人增减和邮箱分配。
app/store.py：数据库迁移、mailbox_owners 邮箱归属、item_owners 每人日报区间、通知队列与留痕。
app/worker.py：读取和分类邮件，按当前负责人合并即时及复核群提醒、邮件兜底及重试；每日完整汇总按负责人发群和邮件，分别记录进度并续发。
app/wecom.py：内部企业微信群 Webhook 配置校验、文本发送和成员 @。
app/config.py：配置校验及加密保存。其他邮件、规则、摘要及发信模块沿用原有职责。

接口
GET /api/state：状态、负责人、邮箱 owners 列表；不返回密钥。
POST /api/connections、POST /api/smtp：自动保存系统与发件箱配置。
POST /api/wecom：自动保存群提醒开关和 Webhook；已有 Webhook 留空保留，不发送测试提醒。
POST /api/people：保存负责人及可选 userid，不发送提醒。
POST /api/people/remove：移除负责人，保留历史记录。
POST /api/person：主动发送测试邮件并记录测试结果。
POST /api/mailbox：保存邮箱，owners 为负责人标识列表，至少一位；兼容旧的单一 owner 参数。
其余邮件列表、日报、台账导出、分类更正、恢复原位置及首次启用接口保留。
